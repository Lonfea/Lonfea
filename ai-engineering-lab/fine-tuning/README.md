# LoRA Fine-Tuning + Preference Alignment Pipeline

A reproducible post-training pipeline for instruction tuning with LoRA, preference optimization with DPO, and before/after evaluation with a catastrophic-forgetting guard.

## Stages

1. validate and version instruction data;
2. SFT with a PEFT LoRA adapter;
3. validate preference pairs;
4. DPO continuation from the trainable SFT adapter;
5. evaluate domain capability before and after;
6. compare a general-capability benchmark to detect excessive forgetting;
7. publish adapters only after the regression gate passes.

## Run

    pip install -e ".[dev]"
    python -m app.train_sft
    python -m app.train_dpo

Training is intentionally **not run in CI** because it requires model downloads and accelerator resources.

## Evaluation integrity

This project does not ship invented before/after metrics. The evaluator expects real result files generated by an actual benchmark run:

- `reports/before.json`
- `reports/after.json`

The gate fails if domain performance declines or the configured general benchmark drops by more than 3 percentage points.

## Default development model

The example defaults to a small Qwen model so the pipeline is inspectable and can be exercised on modest hardware. Model IDs, output paths, and training settings are configurable.

## Why LoRA

PEFT keeps the base model frozen while training a relatively small adapter, reducing memory and compute requirements. The adapter can then be evaluated or merged separately from the original weights.
